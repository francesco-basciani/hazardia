# ADR-0006 — M2 concrete shared data contracts

2026-10-15, accepted implementation choice within authorized M2. No substantial architecture change or new runtime dependency. Records0.4.0: territory, detection, weather ensemble, exposure point, road, resource, intervention; strict discriminated JSON schema, provenance/availability required. Frozen M0 and M1 contracts remain unchanged. M2 records are new explicit types, not automatic migrations or qualifications of M1 metadata. M1 real products are consumed with the existing validator and geospatial leaf reader.

Core uses Python stdlib/jsonschema and SQLite RTree; only leaf `domain.geo` uses existing rasterio/PROJ environment. Geographic coordinates in DTOs are WGS84; first metric profile implementation explicitly supports WGS84 UTM zones32601–32660/32701–32760, other CRS blocked instead of assuming metres. Existing EPSG32633/Abruzzo and32628/syntheticSenegal profiles verified with actual PROJ registry. This is a bounded implementation, not universal geographic qualification.

Snapshots exclusive-create files with canonical content hash/cutoff, source records and excluded future IDs. Event grouping uses configured research time window and overlap with a fixed anchor, not transitive chain merging. Multiple candidate events stay ambiguous. Same-ID changed bytes require explicit new revision; duplicates do not increase confidence. All supporting observations and correlation groups remain visible; conservative score is minimum reported score, not a calibrated probability. Alternatives: unconstrained single-linkage may merge separate events; naive independent fusion can inflate correlated evidence. No new sensor algorithm/scientific superiority claimed.

Ensembles require unique members, aligned complete hourly timelines, explicit units/issue/availability, all unknown weights or normalized explicit weights. Actual M1 ERA5 becomes a one-member REANALYSIS record without invented issue/probability; controlled two-member forecast fixture tests the contract only. Live ensemble/forecast acquisition and alert logic are not M2 results.

Exposure assessment is positive-cell point co-location, with missing/outside/NoData rejected, not a damage/vulnerability/casualty model. Synthetic evacuation count changes remaining exposure while preserving raster identity. PHYSICAL_EFFECT and UNKNOWN_EFFECT cannot claim an improvement without an implemented qualified model; M2 supports no physical intervention effect. Existing simulator/hazard evolution remains separate. Unknown vulnerability remains unknown, not zero damage.

Road/load/time/autonomy and resource-unknown validators prepare constraint inputs; they are not the independent M3 proposal verifier or an authorization system. Synthetic resource/jurisdiction fixtures do not establish actual operational capabilities or permissions. Full network routing, calendars, approvals and policy thresholds remain downstream obligations. No solver, dashboard, model registry, agents, Digital Twin service or third hazard added.
