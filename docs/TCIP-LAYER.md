# TCIP as an optional HAZARDIA layer

The user's26October2026 instruction explicitly authorizes this integration. TCIP remains an independent application and database. HAZARDIA consumes only approved aggregate API products; it imports no TCIP Python package, opens no TCIP database, starts no TCIP collector/model and sends no data to its physical simulators or optimizer.

## Using the layer

Open http://127.0.0.1:8080/?view=map → Livelli → Osservazioni → TCIP · episodi registrati. Enable Mostra livello storico. Choose the full period or Ultimi X anni disponibili, enter a whole number1–100 and apply. Inquadra il livello TCIP frames the country without hiding it under the inspector. Use the region selector for accessible count/share details, or click the drawn zones. The weather timeline remains independent of this historical window.

The current profile is the approved DFP theft subset2018–2020,101 stable published capital labels grouped into20regions. Its empirical share is selected-zone count divided by all released counts in the selected complete years. This is conditional on a recorded episode in the selected dataset, not future crime, personal victimization or population-normalized incidence. Last X ends at the latest observation year, currently2020. Missing/suppressed values stay unknown; if normalization cannot be supported, shares are unavailable. Geometry is separately versioned ISTAT2020 display context, CC BY4.0; no subregional allocation or uniform regional risk is inferred.

## Service boundary and configuration

HAZARDIA retains its existing Linux VM runtime and WII client. For this workstation, independent TCIP is at host127.0.0.1:8010 using its own PostgreSQL/PostGIS. A private SSH reverse forward exposes it only at VM127.0.0.1:18010. No public listener, additional VM, shared database or mandatory WII dependency is introduced.

HAZARDIA runtime `tcip-config.json`:

```json
{"enabled":true,"mode":"client","port":18010}
```

Set enabled:false and restart the owned HAZARDIA web process to disable discovery entirely. The renderer is off by default; normal toggling only affects the map. Invalid/unavailable optional credentials or source data produce a local TCIP error without taking down the framework. There is no model fitting or acquisition behind a map toggle.

A reader token is stored only in `tcip-reader.token` beside the runtime configuration: regular file owned by the runtime user, mode0600, no symlink. Create/revoke/renew it through TCIP's administrator client API/UI. Current credential has products:read only, the20existing release area IDs, official-statistics products only,60requests/minute and30day expiry. It cannot read administrative events or mint browser sessions. The secret is not in source, configuration JSON, browser URLs/storage or responses from the HAZARDIA proxy. Only the token hash is stored by TCIP. One setup credential that could not be persisted was explicitly revoked before replacement.

TCIP's private `.runtime/hazardia-bridge.json` records existing SSH key/known-host paths and loopback SSH/forward ports; it contains no secret key material. `scripts/hazardia_bridge.py start|stop|status` manages only its owned SSH control socket. Once configured, the TCIP desktop launcher tries to reopen this bridge; failure does not block standalone TCIP. This is a current local connection, not an installed always-on scheduler/service. Start TCIP with Avvia TCIP.command and keep its backend active; the VM must already be running. Token renewal is explicit; no indefinite access is granted.

## Wire/API and failure handling

Provider discovery: `GET /api/v1/geo/distributions` with `tcip.map-catalog/1.0`; layer: `GET /api/v1/geo/distribution/{release_id}?years=N`. HAZARDIA exposes its own bounded read-only `/api/tcip/status`, `/api/tcip/layers`, `/api/tcip/layers/{release_id}?years=N`. All calls use same-origin HAZARDIA URLs from the browser; no CORS exception or client-visible credential is required.

The consumer permits a fixed loopback port and fixed GET paths, no redirects/ambient proxies,5second timeout,2MB response cap and two simultaneous reads. It validates the explicit historical profile, release IDs, coordinate ranges/types/size, finite nonnegative counts, NULL shares and the count/denominator/percentage identities. Unsupported CRS/profile/payloads fail closed. Source discovery and layer reads enforce current authorization, whole-release area/product scope and expiry. The proxy returns no-store. While enabled and visible, the browser revalidates every60seconds and clears the earlier layer before loading; failures/revocations are not silent stale fallbacks.
